# 구현 기술과 발전 방향

**작성:** 개발(세션) · 2026-08-22
**근거 문서:** `Bus/7조_버스정류장.md`(원 제안서) · `정류장_스크립트_v1.1.md`/`v2.md` · `Bus/규격/판정_기준.md`

이 문서는 지금 만들고 있는 기술이 원 제안서의 핵심기술과 어떤 관계인지, 어디로 발전시켜야 "새로 만든 것"이라고 주장할 수 있는지를 정리한다.

---

## 1. 원 제안서의 핵심기술 (출발점)

`7조_버스정류장.md`가 정의한 핵심기술: **"연속 파라미터 기반 감정 블렌딩과 구조화된 LLM 생성을 결합한 실시간 서사 블렌딩 시스템"**

- 관객의 자유 발화를 STT+NLU로 분석 → 공포·로맨스·코미디·판타지 **4축 연속 파라미터**(예: H0.7·R0.2·C0.0·F0.1)로 변환
- 이 파라미터를 **물감 섞듯이** 조명·사운드·소품에 실시간 반영 (이산적 "결말 선택"이 아님)
- NPC 대사는 미리 안 쓰고 **RAG+Few-shot+단계별 목표**로 LLM이 그 순간 생성
- 확신도 낮으면 **재질문**, 그래도 애매하면 폴백 기본값
- 소품(고양이 등)은 사전 제작된 여러 버전 중 파라미터 유사도로 즉시 매칭 (지연 회피)
- 지연 구간은 NPC의 미세 동작(들숨 등)으로 "듣고 있다"는 연출로 흡수

이 설계 자체가 이미 스스로 리스크를 인정한 지점이 있다: **"오분류 및 몰입 붕괴 위험 — 자유발화 기반 파라미터 추정이 관객 의도와 어긋날 수 있음"**, **"VR 시연 환경에서 주변 소음 등으로 음성인식 실패 시 대체 입력 수단 필요"**. 음성 하나에만 의존하는 것의 약점이 원안에도 이미 적혀 있다.

## 2. 지금까지 만든 것 — 어디까지 원안이고 어디부터 확장인가

| 원안 요소 | 상태 |
|---|---|
| 음성 STT+NLU 연속 파라미터 추정 | `/api/mood`(Whisper+Claude Haiku)로 이미 구현됨 — 원안 그대로 |
| 재질문 루프 (`vo.reprompt`, `vo.filler1/2`, `sfx.inhale`) | 음성 자산은 녹음·업로드까지 됐지만 **재질문 로직 자체는 미구현** — 부품만 있고 조립 안 됨 |
| 연속 파라미터 블렌딩 | `lib/moodMix.js`가 "상위 2개 배경음 크로스페이드"로 **사운드에 한해 초기 구현됨** |
| LLM 실시간 대사 생성 (RAG+Few-shot) | **미구현** — 고정 46줄(`대사양식_v2.csv`)로 대체됨 (제작비·시간 절감) |
| 판타지 축 | v2 스크립트에서 드롭 — 3축(공포·로맨스·블랙코미디)으로 축소 |

**오늘 밤 새로 추가한 것 — 원안에 없던 확장**: 행동(웹캠 얼굴 인식) 채널. 음성만으로는 위 리스크(오분류·주변 소음·조용한 관객)를 못 푼다는 걸 실제로 겪으면서(입 가림·침묵·웃음 오판 등), 원안이 이미 지적한 문제에 대한 답으로 추가했다.

## 3. 지금 구조의 문제 — 발전이 아니라 후퇴한 지점

행동 채널을 추가하면서 마지막 단계에서 **연속 벡터를 버리고 R/H/C 중 하나만 뽑는 이산 선택(`argmax`)으로 바꿔버렸다.** 이건 원안의 핵심 주장("연속 블렌딩")을 구현 편의상 포기한 것이지, 발전이 아니다. 멀티모달 확장 아이디어 자체는 정당하지만(멀티모달 감정 인식은 실제 연구 분야), 이산화한 채로는 "새로운 걸 만들었다"고 주장하기 약하다.

## 4. 발전 방향 — 이산 선택을 되돌리고 원안의 연속성을 회복

**핵심 통찰: 지금 만든 3채널(행동·텍스트·음성)은 이미 전부 연속 점수를 내고 있다.** `judgeFromBehavior()`, `/api/mood`, `/api/voicetone` 모두 {R,H,C} 0~1 소프트 점수를 낸다 — 마지막 `fuseChannels()`의 `argmax` 한 줄만 이걸 승자 하나로 뭉갠다. 즉 되돌릴 것은 크지 않다.

| 단계 | 내용 | 재사용되는 것 |
|---|---|---|
| 1 | `fuseChannels()`에서 argmax 제거, 연속 벡터 그대로 반환 | 3채널 점수 계산 로직 전부 그대로 |
| 2 | 연속 벡터를 `lib/moodMix.js`에 연결 → BGM 실시간 블렌딩 복원 | moodMix.js 기존 크로스페이드 로직 그대로 |
| 3 | 확신도 기반 재질문 루프 구현 | `vo.reprompt`·`vo.filler1/2`·`sfx.inhale` (이미 녹음됨, 미사용 상태였음) |
| 4 | 그림: 주도 장르 배경 + 보조 장르 비중만큼 색감/조명 틴트 오버레이 | ArtWork_Final 3장 + 각 장르 accent 색 그대로 |
| 5 | 대사: 고정 46줄을 주도 장르 기준으로 재생하되, 보조 장르 비중이 일정 이상이면 그 장르의 짧은 콜백 대사 삽입 | 대사 46줄 + TTS 오디오 그대로 |
| 6(장기) | 대사를 원안대로 RAG+Few-shot LLM 실시간 생성으로 전환 | 위 1~5단계에서 쌓인 파라미터 벡터 파이프라인을 프롬프트 입력으로 그대로 사용 |
| 7(장기) | 파라미터→미디어 속성 매핑을 온톨로지로 정식화, 이미지 생성 모델까지 확장 | 6단계의 파라미터 벡터 구조를 그대로 확장 |

## 5. 판정 채널 자체의 남은 리스크 (별도 문서에 상세)

행동·텍스트·음성 3채널의 신뢰도 문제(임계값 잠정치, 표정 인식 정확도, 실제 검증용 데이터셋 부재)는 이 문서의 범위가 아니라 `Bus/규격/판정_기준.md`에서 계속 관리한다. 이 문서는 "구조를 이산에서 연속으로 되돌리는 것"에 집중한다.
