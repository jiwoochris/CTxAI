## 1. 업무 재분장

각 항목에 "무엇을 하는 건지"와 "왜 필요한지"를 풀어 적었습니다. 프로그램 용어는 최대한 줄였습니다.

### 개발

- [ ] **장르 하나만 뽑던 걸 멈추고, 배합 비율을 그대로 쓰게 바꾸기.** 지금까지는 관객 반응을 보고 "공포다!" 하고 하나만 골랐는데, 이제는 "공포 60%·코미디 40%"처럼 비율 그대로 유지합니다. 원래 기획서(교수님 검토본)가 처음부터 이렇게 섞는 방식을 핵심으로 내세웠기 때문입니다.
- [ ] **배경음악을 실제로 섞어서 틀기.** 위에서 나온 비율(공포 60%·코미디 40%)대로 두 음악의 볼륨을 조절해서 동시에 틀어주는 기능을 만듭니다. 지금은 이 기능이 있긴 한데 실제 완성된 곡이 아니라 테스트용 가짜 소리로만 확인된 상태라, 진짜 곡으로 연결합니다.
- [ ] **관객 답변이 애매하면 한 번 더 물어보게 만들기.** "글쎄요, 잘 모르겠어요" 같은 애매한 대답이 나오면, 이미 녹음해둔 "조금 더 말씀해 주시겠어요?" 음성을 재생하고 한 번 더 대답을 듣습니다. 이 음성 파일들은 이미 만들어져 있는데 지금까지 실제로 쓰이는 곳이 없었습니다.
- [ ] **"애매한 대답인지" 판단하는 기준 새로 만들기.** 위 항목이 작동하려면 "이 정도면 애매한 거다"를 컴퓨터가 판단할 기준이 필요합니다. 이건 순수하게 코드로 계산하는 부분이라 개발이 혼자 처리합니다.
- [ ] **비율 숫자가 너무 자주 흔들리지 않게 다듬기.** 관객이 말을 계속하면 비율이 계속 업데이트되는데, 그때마다 조명이나 음악이 뚝뚝 끊기듯 바뀌면 어색합니다. 부드럽게 이어지도록 처리합니다.
- [ ] **판정 확인용 화면(`/judge`)에서 "장르 하나"가 아니라 "배합 비율"이 보이게 바꾸기.** 개발자/발표자가 지금 시스템이 실제로 뭘 감지했는지 눈으로 확인하는 화면입니다.
- [ ] **실제 체험 화면(`/story`)에서 배합이 느껴지게 만들기.** 주로 나오는 장르의 그림·대사를 기본으로 하고, 두 번째로 강한 장르가 있으면 화면에 살짝 색감을 얹고 대사 한 줄을 끼워 넣어서 "섞인 느낌"을 표현합니다.
- [ ] **판타지 장르 관련 코드 정리.** 판타지를 최종적으로 빼기로 했으니, 코드에 남아있던 판타지 관련 항목들을 지웁니다.

### 기획

- [ ] **AI가 대사를 즉석에서 만들 때 참고할 "이 정류장이 어떤 곳인지" 설정 자료 준비.** 나중에 대사를 사람이 미리 쓰는 대신 AI가 그 자리에서 새로 만들게 할 계획인데, 그러려면 AI에게 "이 세계관은 이런 곳이다"라고 알려줄 참고 문서가 필요합니다. 없으면 AI가 엉뚱한 이야기를 만들 위험이 있습니다.
- [ ] **각 장르별로 "이런 말투로 써주세요" 예시 대사 몇 개씩 준비.** AI에게 실제 잘 쓴 예시 문장을 보여주면 그 톤을 따라 씁니다. 지금 이미 있는 46줄 대사 중 장르별로 대표적인 걸 골라도 됩니다.
- [ ] **이야기 흐름별로 "지금은 무슨 목적의 대사여야 하는지" 정리.** 예: 처음 만났을 때는 "어색함 풀기", 버스가 도착할 때는 "여운 남기기"처럼, 시점마다 대사가 노려야 할 목표를 정해주세요.
- [ ] **"공포가 몇 % 나오면 정류장이 어떻게 달라져야 하는지" 방향 정하기.** 정확한 색상 수치까지는 아니어도, "공포 비중이 높아지면 이런 분위기가 돼야 한다" 정도의 방향을 잡아주시면, 그걸 바탕으로 아트가 실제 색·수치를 정합니다.
- [ ] **테스트할 대표 배합 비율 목록 정하기.** 예전엔 "공포·로맨스·코미디 3가지만 확인하면" 됐는데, 이제 "공포 60%+코미디 40%" 같은 중간 배합도 자연스러운지 확인해야 합니다. 대표로 확인해볼 배합 몇 가지를 정해주세요.
- [ ] **판타지를 빼기로 한 결정이 관련 문서에 다 반영됐는지 마지막으로 한 번 확인.**

### 아트

- [ ] **지금 있는 장르별 그림에서 배경과 인물을 분리한 레이어로 다시 줄 수 있는지 확인.** 두 장르가 섞였을 때, 인물은 그대로 두고 배경 색감만 살짝 바꿔서 "섞인 느낌"을 내려고 합니다. 그러려면 배경과 인물이 따로 분리된 파일이 필요합니다.
- [ ] **기획이 정한 방향 위에 실제 색상 코드·밝기·안개 농도 같은 구체적인 수치 확정.**

### 사운드

- [ ] **완성된 배경음악 3곡(로맨스·공포·코미디)을 실제로 겹쳐 틀어보고 어울리는지 확인.** 예를 들어 공포 60%·코미디 40% 비율로 두 곡을 동시에 볼륨 조절해서 틀었을 때, 원래 따로 들으려고 만든 곡이라 불협화음처럼 들릴 수도 있습니다. 실제로 들어보고 괜찮은지 판단해주세요.
- [ ] **안 어울리면 곡을 다시 손봐야 할 수도 있음.** 세 곡의 음 높이(키)나 박자(템포)를 비슷하게 맞추는 작업이 필요한지 판단해주세요. 위 테스트에서 문제없으면 이 항목은 안 해도 됩니다.
- [ ] **판타지용으로 만들어둔 배경음악을 계속 보관할지 삭제할지 확인.** (급한 건 아닙니다)

## 2. 기술적 문제 재정리 (담당별)

`구현_리스크와_지원_필요사항.md` §4의 6가지 문제를 위 업무 분장에 따라 재배치한다.

| 문제 | 담당 | 비고 |
|---|---|---|
| 그림·인물은 블렌딩이 안 되고 근접 매칭이 필요함 (§4-1) | **개발 + 아트** | 개발은 근접 매칭 로직, 아트는 레이어 분리 자산 제공 |
| 대사 연속성은 결국 LLM 실시간 생성이 있어야만 가능함 (§4-1) | **개발 + 기획** | 기획의 RAG·Few-shot·단계별 목표표가 선행돼야 개발이 붙일 수 있음 |
| 파라미터 → 실제 연출값 매핑표 없음 (§4-2) | **기획 + 아트** | 기획이 방향 정하고 아트가 실제 값 확정, 개발은 그 표를 코드로 옮기기만 함 |
| 값 갱신 시 조명·음량 떨림 (§4-3) | **개발** | 순수 엔지니어링 문제 |
| 확신도(재질문 여부) 판단 기준 재정의 (§4-4) | **개발** | 순수 엔지니어링 문제 |
| 실제 BGM 트랙끼리 겹쳤을 때 음악적 어울림 미검증 (§4-5) | **사운드** | 코드가 아니라 음악 감독 판단 |
| QA 범위가 무한 조합으로 커짐 (§4-6) | **기획 + 개발** | 기획이 대표 지점 정의, 개발이 그 지점들 자동/수동 테스트 |
