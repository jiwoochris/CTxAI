## 5. 지금까지 배운 것 (같은 실수 반복 방지)

- **Supabase Storage 새 형식 키(`sb_secret_...`)는 `Authorization` 헤더만으론 인증 안 됨** — `apikey` 헤더를 같이 보내야 함 (`lib/store.js`의 `authHeaders()` 참고)
- **Supabase Storage는 객체 키에 비-ASCII(한글 등)가 있으면 거부함** — 저장 키는 `slotId+확장자`로 고정, 원래 파일명은 `records.json`에만 보관
- **파일 확장자를 MIME 타입만으로 판정하면 안 됨** — `extensionFor()` 참고
- **`window.prompt()`/`alert()`를 자동화 대상 페이지에서 쓰면 안 됨** — 커스텀 UI로 대체
- **무거운 라이브러리는 동적 import로**
- **브라우저 북마크는 드래그로만 생성 가능** (더 이상 안 씀 — PlayCanvas 제거로 무관해졌지만 기록은 남김)
- **@react-three/fiber는 이 프로젝트(React 18/Next 14)에 v9를 못 씀** — v9/드레이 v10은 React 19 필요. `@react-three/fiber@8.18.0` + `@react-three/drei@9.122.0`로 고정
- **`three` 버전은 `@google/model-viewer`의 peer(`^0.183.0`)와 맞춰야 함** — 안 그러면 두 개의 three 인스턴스가 동시에 로드됨. `three@0.183.0`으로 고정
- **Node에서 GLTFExporter로 테스트 GLB를 만들려면 `FileReader` 폴리필이 필요함** (Node엔 기본 없음) — 굳이 만들 필요는 크지 않음, useGLTF/drei는 브라우저에서 표준적으로 잘 동작함
- **브라우저 자동화 탭을 계속 재사용하며 코드를 여러 번 고치면 IWER(WebXR 에뮬레이터) 상태가 오염돼 캔버스가 죽는 것처럼 보일 수 있음** — 새 탭에서 재현이 안 되면 실제 코드 버그가 아니라 테스트 방식 문제
- **조명 프리셋·할일 목록은 파일이 아니라 Supabase에 저장됨** — 테스트로 아무거나 저장하면 팀 전체가 보는 실제 데이터가 됨. 테스트 후엔 지우거나(프리셋은 storage REST DELETE, 할일은 `DELETE /api/tasks?id=`) 처음부터 진짜 값으로 저장할 것
