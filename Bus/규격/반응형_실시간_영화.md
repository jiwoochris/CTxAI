## 1. 무엇을 바꿨나 — "판정기"에서 "실시간 연출 엔진"으로

8월까지의 구조는 관찰 11초 → 판정 1회 → 고정 장면이었다. 판정 결과가 바꾸는 것은 BGM 볼륨과 그림 한 장뿐이었고, 그 뒤 5분은 관객이 무엇을 하든 같았다. 이 구조에서 "연속 블렌딩"은 볼륨 두 개를 섞는 것 이상이 아니었다.

`/film`은 무게중심을 옮긴다. **연출 상태(direction state)** 하나가 체험 내내 갱신되고, 그 상태가 매 프레임 장면 전체를 움직인다.

```
헤드셋/카메라 포즈 ──┐
웹캠 얼굴(보조)   ──┼─→ 연출 상태 {R,H,C} + settled ─→ 매핑표 ─→ 하늘·태양·안개·가로등·도로 반사
                     │                                          옆사람 거리·시선·침묵 길이·목소리 크기
                     │                                          BGM 게인 · 보조 장르 콜백 대사
                     └──────────────── 관객이 그것을 보고 다시 반응 ──────────────────┘
```

이산으로 남는 것은 둘뿐이다. **누가 앉는가**(로맨스 여성·공포 남성·블랙코미디 할머니, t≈58초에 확정)와 **대사 텍스트**(원문 46줄. `?pool=1`이면 줄마다 보조 장르 변주를 근접 매칭으로 고른다). 나머지는 전부 연속이고, 인물이 앉은 뒤에도 계속 움직인다.

### 2.6 공간 좌표 (2026-09-10 저녁 재배치)

1배속 완주를 화면으로 관찰해 보니 처음 배치는 스크립트의 360° 지도와 어긋나 있었다(도로가 오른쪽으로 달아나고, 벤치가 차선 위에, 유리가 정면에). 아래로 다시 놓았다. 원점은 관객이 앉은 벤치 바닥, 정면은 −z, 오른쪽은 +x, 단위는 미터. 타임라인(`lib/filmTimeline.js`)과 무대(`components/ReactiveStage.jsx`)가 같은 좌표를 쓴다.

| 요소 | 위치 |
|---|---|
| 도로 | 정면에서 좌우(x)로 지나간다. 가까운 연석 z=−3, 중앙 황색선 z=−10, 건너편 연석 z=−17. 가까운 차선 중심 z=−4.75(트럭·버스가 달리는 선) |
| 인도 | z=−1.3 폭 3.4, 관객 뒤 z>2 는 풀숲 |
| 정류장 | 지붕 (0, 2.38, 0.15) 2.4×2.3, 기둥 x=±1.05 · z=1.15/−0.95, 등 뒤 유리 z=1.17, 옆 유리 x=±1.06 |
| 벤치 | PolyHaven `painted_wooden_bench`(원본 1.4m)를 길이만 1.9배로 늘려 2.2m, 중심 (0.6, 0, 0.42), 등받이가 뒤(z≈0.65)로 오도록 π 회전. 관객은 x=0, 옆사람은 x=0.35+거리(상태값 0.7~1.2) |
| 표지판 | 기둥 (−0.95, −2.0), 판 (−0.95, 1.78, −1.9) — 정류장 앞기둥(x=−1.05)에 가려지지 않는 자리 |
| 횡단보도 | x=−5, z −3.9…−16 (8줄) |
| 물웅덩이 | (0.6, −3.9) 타원 — 트럭이 밟고 지나가는 자리 |
| 카페 | (−19, 0, −26) 유리 온실, 문 (−18, −24.4). 우비 인물이 여기서 나와 (−5, −17.6)까지 걸어 트럭을 기다린 뒤 길을 건넌다 |
| 가로등 | (1.6, 1.7) 정류장 옆(공포 트리거), (5.5, −18.6)·(−9.5, −18.6) 건너편 |
| 공원 입구 숲 | +x 쪽 건너편·가까운 쪽 침엽수, 건너편 z≈−19.5 줄에 카페 자리(x −24…−13)만 비움 |
| 고양이 | 오른쪽 공원 진입로 (9, −2.6) → 벤치 앞 (0.9, −1.5) 정지 → 왼쪽 (−9, −2.2) |
| 옆사람 | 왼쪽 인도 (−6, −1.7) → 관객 앞 1.5m 를 지나 벤치 끝 앞 (좌석x+0.15, −1.25) → 돌아서 좌석 (좌석x, 0.3). 관객 코앞 0.5m 안으로는 들어오지 않는다 |
| 버스 | 왼쪽 x=−48 에서 가까운 차선으로 와 차체 중심 x=−1.2 에 정차 — 앞문(차체 앞쪽 2.4m)이 관객 정면 오른쪽 x≈1.2, 연석 쪽 → 오른쪽 x=50 으로 떠난다. 옆사람은 그 문으로 걸어간다 |

**앉은 자세**: 임시 리그(Meshy)는 걷기 클립 하나뿐이라, 정지 프레임(0.35s) 위에 다리·무릎·팔·척추 뼈의 상대 회전(`SIT_POSE`)을 얹어 앉힌다. 실측으로 이 리그들은 뼈 로컬 z 가 앞뒤 굽힘, Head 뼈는 y 가 좌우·x 가 갸웃이다. 그 위에 (1) 숨쉬기(척추·머리 주기 회전), (2) 머리 look-at — 머리→카메라 방위 차를 시선 접촉률(`npcGaze`)만큼, ±70° 안에서 — 로맨스는 관객을 똑바로 보고 공포는 앞만 본다, (3) 앉기·일어서기 0.7초 블렌드(회전과 골반 낮춤을 0→1 로 섞고, 걷기 클립은 블렌드가 0 이 된 뒤 시작)를 얹었다. Mixamo 인물로 바꾸면 Sitting·Stand Up 클립이 (3)을 대신하고 (1)(2)는 그대로 쓸 수 있다. `?rigtest=1`로 두 리그의 서기·앉기를 실제 벤치와 높이 눈금 위에서 점검한다.

**데스크톱 자동 시선**: 헤드셋에서는 관객이 직접 고개를 돌리지만, 화면에서는 옆사람이 오른쪽 90°에 앉아 보이지 않는다. 그래서 XR 세션이 아닐 때 옆사람이 앉으면 카메라가 오른쪽 60°로, 버스가 오면 정면으로 천천히 돌아간다. 드래그하면 8초 동안 멈추고, 자동으로 도는 동안은 "사람에 대한 관심"(옆사람 응시) 측정을 끈다. `?gaze=0`으로 끈다.

## 3. 매핑표 — 무엇이 무엇을 움직이는가

v1.1의 "장르별 하늘과 빛" 표를 수치로 옮긴 것이다. 값은 창작 결정이므로 기획·아트·사운드가 고치면 된다 (`lib/directionMap.js`의 `ANCHORS`).

| 축 | 로맨스 | 공포 | 블랙코미디 |
|---|---|---|---|
| 하늘 | 갈라진 구름 사이 낮은 금빛 | 대낮인데 밤처럼 어두운 두꺼운 구름 | 균일하게 밝은 흐림 |
| 태양 | 고도 14°, 세기 1.55, 따뜻한 색 | 고도 40°, 세기 0.22, 차가운 녹색빛 | 고도 62°, 세기 0.45, 그림자 0 |
| 안개 | 0.020 따뜻한 색 | 0.072 어두운 청록 | 0.016 밝은 노랑 |
| 도로 | 젖은 금빛 반사 0.9 | 어둡고 무광 | 중간 |
| 가로등 | 꺼짐 | **켜짐** (공포 42% 이상이면 예정보다 일찍 점등) | 꺼짐 |
| 옆사람 거리 | 0.55m | 1.2m | 0.85m |
| 시선 접촉률 | 0.75 | 0.12 | 0.5 |
| 대사 사이 침묵 | 0.6초 | 2.3초 | 0.8초 |
| 목소리 크기 | 1.0 | 0.78 | 1.1 |

정착도(settled)가 0이면 중립 앵커(소나기 뒤 흐린 오후), 1이면 배합 앵커가 온전히 적용된다. 증거가 쌓일수록 정류장이 "정해진다".

**사건 수준 트리거** — 파라미터가 슬쩍 바뀌는 것이 아니라 무언가가 일어나야 관객이 알아챈다.
- 공포 ≥ 42%: 정류장 뒤 가로등이 아직 오후인데도 켜진다 (v2 공포 트랙 원문)
- 로맨스 ≥ 45%: 구름이 갈라지고 태양 광원이 뚜렷해지며 도로 반사가 오른다
- 코미디 ≥ 45%: 그림자가 완전히 사라진다
- 보조 장르 ≥ 25%: 그 장르의 첫 대사가 콜백으로 한 줄 끼어든다

## 4. 센서 — 헤드 포즈가 1순위, 웹캠은 보조

헤드셋을 쓰면 얼굴 상반부가 가려져 웹캠 표정 인식(눈 크게 뜸·눈썹)은 불가능하다. 그래서 **헤드 포즈가 1순위 신호**이고, 웹캠은 얼굴이 잡힐 때만(헤드셋을 안 쓴 데스크톱 관람) 8초 창으로 보조 증거를 넣는다. 얼굴이 창의 60% 이상 안 잡히면 그 창은 버린다 — 헤드셋 착용을 "얼굴 없음 = 강한 반응"으로 오판하지 않기 위해서다.

증거 무게: 음성 텍스트 0.9 > 사건 채점(물보라·고양이 1.0, 나머지 0.8, **보지 않은 사건은 0.25**) > 웹캠 창 0.5 · 음성 톤 0.5 > 상시 창 0.35. 보지 않은 사건을 가볍게 두는 이유: 사건 두어 개에 분명히 반응한 관객이 나머지를 안 봤다는 이유로 로맨스로 뒤집히면 안 된다. **반응이 전혀 없는 창은 아무것도 넣지 않는다** — "반응 없음 = 로맨스"는 도입부 사건 채점이 이미 담당하고, 장면 내내 로맨스를 계속 넣으면 도입부 반응이 지워진다(실측: 5분 장면 끝에 늘 로맨스로 수렴하던 문제). 반감기 150초로 도입부 채점이 장면 끝까지 남는다. 임계값은 전부 잠정치이며, 파일럿 실측으로 고쳐야 한다 (`headPoseSense.js` 상단 상수).

## 6. 인프라 — OpenRouter 하나로

- Supabase·Vercel·ElevenLabs에 의존하지 않는다. 오디오는 `scripts/pull-assets.mjs`로 받은 로컬 파일(46줄 대사·SFX 18종·BGM 3트랙·안내방송)만 쓴다.
- `/api/dialogue`(실시간 대사 생성)는 Anthropic SDK 직접 호출에서 OpenRouter `anthropic/claude-haiku-4.5`(json_schema 구조화 출력)로, `/api/tts`는 ElevenLabs에서 OpenRouter `openai/gpt-audio-mini`로 바꿨다. 실측: OpenRouter 오디오 출력은 `stream:true`가 필수이고 스트리밍 포맷은 `pcm16`(24kHz 모노)만 되므로, 서버가 SSE 조각을 모아 WAV로 감싸 돌려준다. 한국어 문장을 정확히 낭독하는지 확인했다(덧붙임 방지 지시 포함). `/api/mood`·`/api/voicetone`는 원래 OpenRouter였다. 이제 외부 키는 `OPENROUTER_API_KEY` 하나다.
- 로컬 실행: `npm run film` (= `env -u NODE_ENV -u TURBOPACK next dev`). 이 맥의 셸에 비표준 `NODE_ENV`·`TURBOPACK`이 잡혀 있어 그냥 `next dev`를 띄우면 CSS 로드와 빌드가 깨진다. 빌드는 `npm run build:clean`, 회귀 테스트는 `npm test`.

## 7. 남은 일 (우선순위)

1. **헤드셋 실측** — Quest 3에서 `/film` 진입, 헤드 포즈 센서 임계값(±28° 응시 허용, 140°/s 화들짝, 7cm 후퇴) 보정. 데스크톱 드래그로는 후퇴 신호가 없다.
2. **파일럿 10~20명** — 종료 카드의 "당신이 느낀 정류장은?" 버튼으로 자기보고를 받으면 `data/sessions/`에 자동 저장되고 `GET /api/session`이 일치율을 계산한다. 이 숫자가 이 프로젝트의 유일한 기술적 근거가 된다.
3. **인물 하나로 합칠지 결정** — 지금은 세 인물이 이산이다. 인물 하나에 태도 클립(요청서 v5.0 §2.7의 `att_*` 5종)을 블렌딩하면 "분기"가 완전히 사라진다. GLB 리그가 오면 바로 붙일 수 있게 `Person` 그룹을 분리해 두었다.
4. **대사 사전 생성 풀 — 1차 구현됨** (`?pool=1`). 남은 것은 (a) 변주 텍스트를 기획이 검수·수정하고 (b) 목소리를 확정하는 일이다. 지금 풀의 목소리는 OpenRouter 합성이라 원문 46줄(ElevenLabs)과 다르다. 풀 모드에서는 원문도 같은 합성 목소리로 재생해 한 인물의 목소리가 바뀌지 않게 했다.
5. **음성 채널 — 선택 옵션으로 구현됨** (`?voice=1`). 안내방송 뒤 "당신은 무엇을 기다리고 있습니까?"를 묻고, 답을 STT+LLM(`/api/mood`)과 톤 분석(`/api/voicetone`)에 보내 텍스트 0.9·톤 0.5 무게로 증거에 넣는다. 답이 없으면 채움말·들숨·되묻기 1회. 답에서 뽑은 명사는 정류장 이름 표지판에 "{명사} 앞"으로 쓴다(요청서 v5.0 §2.6, 글자 값은 D5). 판정(누가 앉는가)에는 안 들어가고 앉은 뒤의 장면을 바꾼다 — v2 스크립트의 "말하지 않아도 판정" 원칙을 지키기 위해서다. 마이크 없이 점검하려면 `?voicefake=horror`(public/samples). **켤지 말지는 기획 결정으로 남긴다** — 켜면 어두운 전시장의 마이크 오염(§3.3)을 동선으로 막아야 한다.
6. **인물 — Mixamo 동작 붙이기 (Blender 설치됨, Mixamo 로그인 필요).** 사람은 아직 Meshy 임시 리깅이라 앉기 동작이 없고, 지금은 정지 프레임 위에 뼈 상대 회전(`SIT_POSE`)을 얹어 앉힌 것이다 — 머리가 몸의 세 배인 카툰 비율이라 옆에 앉으면 화면을 머리가 채운다. 준비는 끝나 있다: Blender 5.2가 `/opt/homebrew/bin/blender`에 설치됐고, `scripts/blender/mixamo_to_glb.py`가 인물 FBX 하나와 동작 FBX 여러 개를 GLB 하나로 합친다. **남은 것은 Mixamo(Adobe 계정)에서 FBX를 내려받는 일뿐이다** — 이 세션의 브라우저는 로그인이 안 돼 있었다.
   1. https://www.mixamo.com 로그인 → Characters에서 인물 셋(젊은 여성 / 중년 남성 / 나이 든 여성에 가까운 것) 고르기 → Download: Format FBX Binary, Pose T-pose, **With Skin** → `character_R.fbx` 등
   2. 같은 인물로 Animations에서 `Sitting Idle`, `Sitting Talking`, `Stand Up`, `Walking`, `Idle` 검색 → Download: FBX Binary, **Without Skin**, 30 fps → 파일명을 동작 이름으로
   3. `blender -b -P scripts/blender/mixamo_to_glb.py -- character_R.fbx public/reactive/models/rigR.glb "Sitting Idle.fbx" "Sitting Talking.fbx" "Stand Up.fbx" Walking.fbx Idle.fbx` → `npx @gltf-transform/cli meshopt public/reactive/models/rigR.glb public/reactive/models/rigR.glb`
   4. `RiggedPerson`이 클립 이름으로 상태를 고르게 바꾼다: 걷기 → `Walking`, 착석 → `Sitting Idle`, 대사 재생 중 → `Sitting Talking`, 버스 도착 → `Stand Up`. 머리 look-at은 `mixamorig:Head` 뼈에 시선 접촉률을 적용.
   트럭·고양이·버스는 코드 지오메트리다. 아트 GLB가 오면 `ReactiveStage.jsx`의 `RiggedPerson`·`Truck`·`Cat`·`Bus`만 바꾼다. 지형은 3D_배경_구성_기획.md §2 원칙대로 고정.
