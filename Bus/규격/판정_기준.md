# 판정 기준 — 행동·텍스트·음성 3채널

**작성:** 개발(세션) · 2026-08-22 · **상태: 초안 — 파일럿 테스트 전 잠정치**

이 문서는 관객이 헤드셋 없이도(웹캠, 추후 IR 카메라) 장르 판정을 받을 수 있도록 `정류장_스크립트_v2.md` §2의 판정 기준을 실제 신호로 구현한 설계입니다. 임계값은 전부 잠정치이며, `v2.md` §2 마지막 경고("파일럿 테스트 전 잠정치")와 같은 성격의 리스크를 그대로 안고 있습니다.

## 1. 동공인식(눈동자 추적) — 검토했으나 채택 안 함

`@mediapipe/tasks-vision`의 FaceLandmarker는 홍채 랜드마크(468~477번)도 출력해서 기술적으로는 웹캠만으로 대략적인 시선 방향 추정이 가능합니다.

**채택하지 않는 이유**
- `v2.md` §5에 이미 "'시선'의 정의 — 확정: 헤드셋 헤드 포즈(머리 위치·회전) 기준. 눈동자 추적 아님"이라고 못박혀 있음 — 팀이 이미 검토 후 머리 자세 쪽으로 정리한 것으로 보임.
- 홍채 추적은 머리 자세보다 훨씬 높은 해상도·근접 거리·고른 조명이 필요함. 실제 전시는 어두운 공간이라 IR 카메라로 갈 예정인데, 홍채 디테일은 거친 얼굴 윤곽보다 IR 저조도에서 훨씬 쉽게 깨짐.
- 구현·캘리브레이션 범위만 늘고 판정 신뢰도는 오히려 불안정해질 가능성이 큼.

**결론: 눈동자 추적 미채택, 머리 자세(웹캠 대용 신호)만 사용.**

## 2. 스크립트가 유도하는 행동 — 정면 카메라로 판정 가능한가

`v2.md` §1의 5가지 사건을 정면 카메라(웹캠 → 추후 IR 카메라로 교체돼도 배치는 동일) 기준으로 검토.

| 사건 | 방향 | 정면 카메라 감지 |
|---|---|---|
| 찢어진 포스터 (§1-1) | 관객 오른쪽 유리, 근거리 | ✅ 가능 — 정면 인식 범위(약 ±60~75도) 안 |
| 카페·우비 인물 (§1-2) | 전방 왼쪽 50m, 장시간 추적 | ✅ 가능 — 완만한 좌측 응시 지속, 정면 범위 안 |
| 트럭 물보라 (§1-3) | 관객 정면 가까이 | ✅ 가능 — 움찔·후퇴가 "뒤로 빠짐"(얼굴 크기 축소)으로 잘 잡힘 |
| 고양이 2단계 사건 (§1-5) | 오른쪽 등장 → 왼쪽 가로지름 | ✅ 가능 — 좌우 스윕, 정면 범위 안 |
| **개구리 (§1-4)** | **오른쪽 "뒤", 약 45도(등 뒤 쪽)** | **⚠️ 사실상 불가능 — 정면 카메라의 사각지대** |

개구리 사건만 문제입니다. 확인하려면 고개를 옆얼굴 이상으로 돌려야 하는데, 이는 정면 카메라의 얼굴 인식 한계(약 ±60~75도)를 넘어섭니다. 이 각도에서 얼굴 인식 자체가 끊깁니다.

**대응**: 실패로 두지 않고 신호로 씁니다. 관찰 창 동안 "**얼굴을 완전히 놓친 시간**"(`lostTrackingSec`)을 별도 지표로 기록 — 개구리 타이밍 즈음 얼굴이 사라지면 강한 반응(정확한 방향은 몰라도 고개를 크게 돌렸다는 사실)으로 처리합니다.

**로드맵**: 이 사각지대는 단일 정면 카메라의 근본적 한계입니다. 완전히 풀려면 헤드셋(전방향 IMU) 또는 후방 보조 카메라가 필요 — 지금은 하드웨어 우선순위 밖.

## 3. 세 개의 독립 판정 채널

"무슨 말을 했는가"(텍스트)와 "어떻게 말했는가"(음성 톤)는 다른 정보라 분리합니다.

### 채널 A — 행동 (`lib/behaviorSense.js`)
웹캠 얼굴 랜드마크로 11초간 관찰. 코 끝(landmark 1)의 얼굴 중심 대비 좌우/상하 치우침, 얼굴 폭 변화(뒤로 빠짐 대용), 방향 전환 횟수, 지속 이탈 시간, 회복 속도를 계산해 `{R, H, C}` 소프트 점수로 변환. `v2.md` §2-4의 우선순위(공포→블랙코미디→로맨스)와 조건을 그대로 반영.

**2026-08-22 갱신 — 좌표 계산 외에 실제 학습된 표정 인식 모델도 사용.** 리허설 중 **입을 손으로 가리기만 해도 턱 랜드마크가 흔들려 공포로 오판**되는 문제가 나왔습니다. 두 가지로 고쳤습니다:
1. 세로축 기준점을 턱(152번, 손에 가려지기 쉬움)에서 미간(168번, 손이 잘 안 가리는 부위)으로 변경
2. 한 프레임 안에서 물리적으로 불가능한 급격한 좌표 튐(`MAX_FRAME_JUMP`)은 인식 오류로 보고 버림

여기에 더해 **MediaPipe FaceLandmarker에 내장된 얼굴 표정 인식 모델(ARKit 호환 블렌드셰이프 52항목, 실제 얼굴 캡처 데이터로 학습됨 — 제가 지어낸 규칙이 아닌 모델 출력값)을 켜서** 공포/놀람 관련 항목과 웃음 관련 항목 점수를 `maxFear`·`maxAmusement`로 뽑아 판정에 같이 반영합니다. 좌표 기반 추정(내 임의 임계값)과 학습된 표정 모델(근거 있는 출력값)을 섞어서, 좌표만으로 오판하는 사례를 줄입니다.

**2026-08-22 추가 갱신** — 리허설 중 **웃었는데 공포로 판정되는** 버그 발견, 두 가지 원인:
1. 공포 신호에 `jawOpen`(입 벌어짐)을 넣어뒀는데, 크게 웃을 때도 입이 벌어져서 혼동됨 → `jawOpen` 제거, `eyeWideLeft/Right`·`browInnerUp`(웃음과 안 겹치는 특이적 공포 신호)만 남김
2. 웃을 때 고개를 뒤로 젖히는 자연스러운 동작을 "겁먹어서 뒤로 뺌"으로 오판 → 표정 모델이 뚜렷한 웃음(`maxAmusement`)을 감지했으면 방어 신호(`defensiveSig`)를 그만큼 깎도록 교차 억제 추가

### 채널 B — 텍스트 (`lib/textKeywords.js`, `/api/mood`)
**2026-08-22 갱신 — 키워드 사전은 판정에서 뺐습니다.** 처음엔 STT 전사문을 직접 만든 한국어 키워드 사전(무섭다·소름 등)과 대조해서 점수를 매겼는데, 그 사전 자체가 말뭉치·연구 근거 없이 제 직관으로 나열한 것이라는 지적을 받았습니다. 지금은 `/api/mood`(Whisper STT + Claude Haiku 의미 분석)의 점수를 그대로 씁니다 — 모델이 문장 전체 의미로 판단합니다. 여기에 **모델한테 "왜 이렇게 채점했는지" 한 줄 근거(`reason`)도 같이 받도록** 프롬프트를 바꿔서, 대시보드에서 판정 근거를 볼 수 있게 했습니다. 키워드 사전(`GENRE_KEYWORDS`)은 코드에 남아 있지만 이제 대시보드에 "참고용" 하이라이트만 보여줄 뿐 점수 계산엔 안 씁니다.

### 채널 C — 음성/톤 (`lib/voiceProsody.js`, `/api/voicetone`)
**2026-08-22 갱신 — RMS·영교차율 자체 계산 대신, 실제 오디오를 이해하는 멀티모달 모델을 기본으로 씁니다.** 처음엔 Web Audio로 에너지·무음 비율·영교차율을 재서 방향성 있는 규칙(제 임의 매핑)으로 점수를 냈는데, 이건 세 채널 중 근거가 가장 약했습니다. 지금은 녹음된 오디오를 (ffmpeg 없이 브라우저에서 직접 WAV로 변환해) OpenRouter의 오디오 이해 모델(`google/gemini-2.5-flash`, 이미 쓰는 키로 호출)에 보내서 "내용 말고 톤·에너지·떨림만 보고 채점해 달라"고 직접 물어봅니다. 모델 호출이 실패하면(네트워크 등) 기존 RMS 휴리스틱으로 폴백합니다 — 대시보드에 어느 경로로 나온 점수인지(`model` / `heuristic_fallback` / `no_speech`) 표시됩니다.

리허설 중 **아무 말도 안 했는데 음성 점수가 나오는** 버그도 있었습니다 — 무음 비율을 클립 자체의 평균 대비 상대값으로만 재서, 완전한 침묵도 절반은 "상대적으로 덜 조용한 프레임"으로 잡혀 점수가 만들어졌음. 절대 에너지 기준(`NO_SPEECH_RMS`) 밑이면 발화 자체가 없다고 보고 이 채널을 신호 없음(null)으로 빼도록 수정 — 모델 호출도 이 경우엔 아예 안 해서 비용을 아낌.

### 로드맵 — AI Hub 데이터 기반 자체 모델 (지금은 안 함)
[AI Hub](https://www.aihub.or.kr/)에 "시나리오 기반 표정 3D 데이터"(약 917GB) 등 감정 인식용 데이터셋이 있습니다. 다만 AI Hub는 **실시간 API가 아니라 다운로드용 학습 데이터 저장소**라, 쓰려면 로그인/신청 후 다운로드해서 **직접 모델을 학습**시켜야 합니다 — 이 자체가 며칠~몇 주짜리 별도 프로젝트라 이번 발표엔 못 씁니다. **실제 전시용 최종 버전에서는** 이런 데이터로 직접 학습한 한국어 특화 표정·음성 감정 모델로 교체하는 걸 로드맵으로 남깁니다.

## 4. 판정 애매할 때의 디폴트 — 로맨스

`v2.md` §2-4-C에 이미 문서화됨:

> "로맨스는 소극적 관객을 위한 낮은 단계가 아니라, 반응이 적어도 혼자 이야기를 이끄는 안정적인 디폴트 드라마다."

`v1.1.md` §2 근거: 로맨스 캐릭터는 관객이 무반응이어도 혼자 대화를 끌고 가도록 설계됨. 공포는 관객의 긴장, 블랙코미디는 관객의 웃음이 전제돼야 장면이 사는데, 로맨스만 무반응을 그대로 흡수할 수 있음.
